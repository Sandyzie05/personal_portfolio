# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — manual CSS design system (no `components.json` detected; greenfield project) |
| Preset | not applicable |
| Component library | none (hand-built components — no Radix/shadcn primitives needed; this phase has no complex interactive widgets, only static content sections, anchor-nav links, and plain cards) |
| Icon library | `lucide-react@1.25.0` (peer `react ^16.5.1 \|\| ^17 \|\| ^18 \|\| ^19` — compatible with this project's React 19.2.7 pin; verified against npm registry 2026-07-19). Used for: Contact section icons (email/LinkedIn/GitHub/download), mobile nav hamburger/close icons, external-link indicator glyph on project cards |
| Font | Primary: **Inter** (variable, self-hosted or `@fontsource/inter`) for all body/heading/UI text. Accent: **JetBrains Mono** for technical/code-style labels only (skill category chips, project tech-tag pills, nav wordmark) — reinforces the SRE/platform-engineer technical register without competing with Inter for primary reading |

**Rationale for "Tool: none":** RESEARCH.md's already-committed project structure (`src/index.css`, no `tailwind.config.*`/`components.json` anywhere in the recommended structure) is plain CSS with typed content modules. A component-library framework (shadcn/Tailwind) would add build complexity with no clear benefit for a single-owner, content-only portfolio shell with no forms, no complex widgets, and no data tables in this phase. Plain CSS custom properties (design tokens below) also give full control over the semi-transparent "backdrop" card treatment needed for forward-compatibility with Phase 2/3's WebGL background — fighting a component library's own surface/elevation system would work against that goal. **This is an assumption made under D-09/D-10's granted discretion, not a user-confirmed choice** — flag for confirmation if a component library is preferred later; introducing shadcn afterward remains straightforward since no shadcn-shaped code exists yet to migrate away from.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tag/chip internal padding |
| sm | 8px | Compact spacing (tag row gaps, meta-line gaps within a card) |
| md | 16px | Default element spacing (paragraph gaps, card internal padding on mobile) |
| lg | 24px | Card internal padding (desktop), gap between cards in a grid |
| xl | 32px | Gap between a section's heading and its content |
| 2xl | 48px | Vertical padding between major page sections (mobile) |
| 3xl | 64px | Vertical padding between major page sections (desktop) |

Exceptions: Mobile nav hamburger toggle button uses a 44×44px hit target (WCAG 2.5.5 minimum touch target) even though its visible icon is 24px — the extra hit area is invisible padding, not a new spacing token. No other exceptions this phase (no icon-only touch controls beyond the mobile nav toggle — the theme picker/opacity slider from BG-01/BG-04 are Phase 3, out of scope here).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.6 |
| Label | 14px | 700 (bold) | 1.4 |
| Heading | 32px | 700 (bold) | 1.2 |
| Display | 48px | 700 (bold) | 1.1 |

**Only 2 weights total across the whole site: 400 and 700.** Label uses 700 at small size (an "eyebrow"/tag treatment — bold + letter-spacing, not a third weight) rather than introducing 500/600.

**Responsive scaling:** Display clamps between mobile and desktop rather than using a single fixed size: `font-size: clamp(2rem, 5vw + 1rem, 3rem)` (32px–48px) so the hero name/headline never overflows small viewports. Heading (section titles, e.g. "Experience", "Projects") stays fixed at 32px across breakpoints — it never needs to shrink further and a fixed size keeps section rhythm predictable.

**Mono accent usage (JetBrains Mono, same size/weight tokens as above, font-family swapped only):** project tech-tag pills (PROJ-01), skill category chip labels (SKILL-01/02), and the nav wordmark/logotype. Never used for body copy, headings, or testimonial quotes — reserved strictly for short, technical-feeling labels.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F17` | Page background (full-bleed `<body>`/`<html>` background — this is also the surface Phase 2/3's WebGL canvas will render behind/into) |
| Secondary (30%) | `#111620` at 72% opacity (`rgba(17,22,32,0.72)`) + `backdrop-filter: blur(16px)` (solid `#111620` fallback where `backdrop-filter` is unsupported) | Section cards (Project cards, Testimonial cards, Certification/Education list rows), sticky top nav bar, footer bar |
| Accent (10%) | `#22D3EE` (electric cyan) | Reserved for exactly: (1) primary CTA button fill/border ("Download Resume"), (2) active/hovered nav-link underline indicator, (3) project-card hover border glow, (4) the small marker dot preceding each Experience achievement bullet, (5) the `:focus-visible` outline ring site-wide (keyboard navigation) |
| Destructive | `#F87171` (soft red) | Reserved only — no destructive user actions exist in this phase (static content site, no forms/deletes). Held in reserve for a future broken-content/error-boundary indicator (see Copywriting Contract's Error row) |

Accent reserved for: primary CTA fill/border, active nav-link indicator, project-card hover glow, experience-bullet marker dots, `:focus-visible` ring. **Never** applied to body text links, section headings, or as a general "brand color wash" — those stay in the primary/secondary text colors below.

**Supplementary text-on-dark tokens (not template rows, but required for an actionable dark-mode contract):**

| Token | Value | Usage |
|-------|-------|-------|
| Text primary | `#E8ECF1` (off-white, not pure `#FFFFFF`) | Headings, body copy, testimonial quotes |
| Text muted | `#94A3B8` (slate gray) | Dates, role/location meta lines, card sub-labels, footer copyright line |

Both pass WCAG AA contrast (4.5:1+ for body text, 3:1+ for large text) against both the `#0B0F17` dominant background and the `#111620` secondary card surface — verify with a contrast checker at implementation time (QUAL-04).
